# 주도섹터 ↔ K-ETF 운영 콘솔

장 마감 후(종가 기준) 네이버금융 수급 데이터를 보고 주도 섹터와 K-ETF를
한 흐름으로 점검하는 정적 웹 도구.

## 구성

| 파일 | 설명 |
|------|------|
| `index.html` | 통합 콘솔(껍데기). 아래 두 도구를 iframe으로 불러옴 |
| `sector_tracker_v1_8.html` | 🗺 주도섹터 트래커 (시장 지도 · 톱다운) |
| `ketf-v3_2_2.html` | 💼 K-ETF 헤게모니 (진입·사이징 · 보텀업) |
| `netlify/functions/proxy.js` | 네이버금융 CORS 우회용 서버리스 프록시 |
| `netlify.toml` | Netlify 게시/함수 설정 |

## "페치 실패"가 나던 이유와 해결

두 도구는 브라우저에서 `finance.naver.com` 데이터를 직접 못 가져온다(CORS).
그래서 공개 CORS 프록시(codetabs / allorigins / corsproxy.io)를 순서대로
시도하는데, 이 무료 프록시들이 자주 다운·차단·레이트리밋되어 셋 다 실패하면
**"페치 실패"**가 떴다.

해결:

1. **자체 Netlify 함수 프록시를 1순위로 추가** — 남의 프록시에 의존하지 않음.
   `/.netlify/functions/proxy?url=...` 가 서버 쪽에서 네이버를 대신 호출.
2. 함수가 없는 배포(드래그&드롭 등)에서는 그 호출이 404로 **즉시 실패 → 기존
   공개 프록시로 자동 폴백**하므로 어느 배포 방식이든 안전.
3. 섹터 트래커에 **빠져 있던 요청 타임아웃(15초)** 추가 — 프록시 하나가
   응답 없이 매달리는 문제 방지.

### 자체 프록시를 켜려면 (가장 안정적)

Netlify에 **Git 연동** 또는 **Netlify CLI**(`netlify deploy --prod`)로 배포하면
`netlify.toml` 설정에 따라 함수가 자동 활성화된다. 폴더 드래그&드롭으로
올리는 경우 함수는 동작하지 않지만, 위 2번 폴백 덕분에 사이트는 그대로 동작한다.

자체 프록시 정상 동작 여부는 도구 상단의 프록시 상태 표시가
`netlify` 로 뜨는지로 확인할 수 있다.
